# 学生画像分析系统 · 软件需求规格说明书（SRS）

**文档版本**：v1.0
**最后更新**：2026-09-15
**适用范围**：高校学生数据可视化驾驶舱前端

---

## 1. 项目范围

### 1.1 项目背景

高校每年产生大量学生数据——成绩、考勤、一卡通消费、社团活动、综测评分、奖励处分——这些数据分散在教务、学工、后勤等多个独立系统中，老师和辅导员想要了解一个学生或一个学院的真实情况，往往需要登录五六个系统反复查询、手工对比。

本系统的目标是把这些分散的数据汇聚成两张直观的**画像**，让使用者在一个页面上就能快速回答两个问题：

1. **"这个学生怎么样？"** —— 个体画像视图
2. **"这个学院/年级怎么样？"** —— 群组画像视图

### 1.2 做什么（In Scope）

| 编号 | 内容 |
|------|------|
| 1 | 提供一个可视化的单页 Web 应用，包含三个顶层导航入口：**个体画像**、**群组分析**、**学生画像查询** |
| 2 | 个体画像：为单个学生提供综合视图，包含个人信息、3D/图像人物展示、综测雷达图、校园活动统计、成绩趋势、日常生活数据、成长标签 |
| 3 | 群组分析：为学院/群体提供宏观统计，包含学生人数概况、政治面貌、年龄结构、生源地地图、少数民族排行、综合素质趋势、请假情况 |
| 4 | 学生画像查询：支持按学号/姓名、学院、年级、性别、状态等条件筛选，结果列表展示，点击行可直接进入对应学生的个体画像 |
| 5 | 所有数据用 ECharts 图表可视化呈现（雷达、环形、折线、柱状、中国地图、排行条形） |
| 6 | 响应式大屏适配：页面最小宽度 1280px，适合 1920×1080 及以上显示器 |
| 7 | 支持"数据源为空"时的优雅降级（如地图加载失败显示条形图，3D 模型失败显示兜底人偶） |

### 1.3 不做什么（Out of Scope）

| 编号 | 内容 | 原因 |
|------|------|------|
| 1 | **后端服务 / API** | 当前阶段为纯前端原型，数据全部 Mock；后续接入真实后端是下一阶段工作 |
| 2 | **用户登录 / 权限系统** | 暂不区分角色权限；当前所有数据对所有使用者可见 |
| 3 | **数据的增删改**（录入、编辑、审核） | 本系统定位是"读多写少"的查询与可视化，不承担数据录入职责 |
| 4 | **消息推送 / 预警通知** | 不做"挂科预警""绩点下滑提醒"等主动推送 |
| 5 | **移动端适配** | 本系统是驾驶舱，只面向 PC 大屏，不做手机/平板 UI |
| 6 | **学生自助查看个人画像** | 目标用户是老师和辅导员；不给学生提供登录和查看入口 |
| 7 | **导出 Excel / PDF 报表** | 后续版本考虑 |
| 8 | **实时数据流 / 大屏轮播** | 数据不要求毫秒级实时；当前以"打开页面拉一次数据"为模式 |
| 9 | **拖拽交互**（如手动调整图表布局、拖拽分组） | 暂不实现复杂交互 |
| 10 | **学生成绩预测 / AI 推荐** | 本系统只展示数据，不做预测 |

## 2. 用户角色

### 2.1 辅导员 / 班主任

- **使用频率**：高（每周多次）
- **核心诉求**：快速看到自己班级 45~50 个学生里"谁在后面"、"谁成绩下滑了"、"谁请假多"
- **主要操作**：
  - 学生画像查询 → 筛选自己班级 → 逐个点进个体画像
  - 群组分析 → 选择自己学院的年级 → 看年龄分布、综测不合格名单
  - 个体画像 → 看综测雷达图判断"这学生实践能力差还是学习能力差"

### 2.2 学院教学秘书

- **使用频率**：中（每周 1~2 次，或开学/期末密集使用）
- **核心诉求**：掌握整个学院的学风、生源结构、综测情况
- **主要操作**：
  - 群组分析 → 切换不同学院/年级 → 对比政治面貌、年龄、生源地分布
  - 综合成绩发展 → 看近 5 年综测平均分趋势，判断本学院教学质量变化

### 2.3 学工部门 / 校级管理员

- **使用频率**：低（每月几次，主要用作会议汇报和决策支持）
- **核心诉求**：宏观数据一览，做年度报告和政策评估
- **主要操作**：
  - 群组分析 → 切换"全校"级别 → 看全貌
  - 生源地地图 → 判断哪些省份生源质量高、哪些省份需要加强招生
  - 少数民族排行 → 了解少数民族学生占比

## 3. 功能需求

> **注意**：以下每条都是**用户能完成什么**，不是**系统内部怎么实现**。

### 顶层导航

| 编号 | 功能 |
|------|------|
| FR-01 | 用户应能通过顶部导航在"个体画像"、"群组分析"、"学生画像查询"三个视图之间切换 |
| FR-02 | 切换视图时，正在显示的图表不应报错、不应黑屏、不应残留上一个视图的数据 |

### 个体画像视图

| 编号 | 功能 |
|------|------|
| FR-03 | 用户应能看到一个学生的头像、姓名、学号、性别、学院、专业 |
| FR-04 | 用户应能看到该学生的**综测成绩**（分数 + 较去年涨跌）和**班级排名**（第几名 + 较去年涨跌） |
| FR-05 | 用户应能看到该学生在**思想品德、学习能力、实践能力、创新能力、身体素质、文化素养**六个维度上的雷达图，并能同时看到班级最高分和班级均分作为对比 |
| FR-06 | 用户应能看到该学生的**校园活动统计**：总活动次数，以及文体/竞赛/社会实践/志愿服务各分类的占比 |
| FR-07 | 用户应能看到该学生**近 3 个学期**的必修课和选修课成绩趋势折线图 |
| FR-08 | 用户应能看到该学生**日常生活数据**：一卡通余额、本月借阅图书、本月上网时长、本月请假次数 |
| FR-09 | 用户应能看到该学生的**荣誉徽章标签**（如"优秀学生""CET-6""国家奖学金"） |
| FR-10 | 用户应能看到该学生的**获奖总数、奖学金金额、荣誉称号数、违纪处分次数** |
| FR-11 | 用户应能在个体画像视图的**二级 Tab 栏**切换"总览/日常生活/校园活动/奖惩信息/资助信息/学业信息/成长轨迹"（当前阶段默认停留在总览） |

### 群组分析视图

| 编号 | 功能 |
|------|------|
| FR-12 | 用户应能在群组分析顶部切换**全校 / 学院**范围，并能通过下拉框选择具体学院 |
| FR-13 | 用户应能看到选定范围内的**学生总数、在籍人数、不在籍人数、男生数、女生数** |
| FR-14 | 用户应能看到选定范围的**政治面貌分布**（中共党员、预备党员、共青团员、其他、群众）环形图 |
| FR-15 | 用户应能看到选定范围的**学生年龄结构**（18 岁以下、19、20、21、22 岁及以上）横向柱状图 |
| FR-16 | 用户应能看到选定范围的**生源地中国地图**，不同省份用颜色深浅表示人数 |
| FR-17 | 用户应能看到选定范围的**少数民族排行榜**（民族名称 + 人数 + 占比） |
| FR-18 | 用户应能看到选定范围的**综合素质发展**：合格 vs 不合格比例环，以及**近 5 年综测平均分趋势折线图** |
| FR-19 | 用户应能看到选定范围的**近 7 天学生请假情况**折线图 |
| FR-20 | 用户应能在群组分析视图的**三级 Tab 栏**切换"基本信息/日常生活/校园活动/奖惩信息/资助信息/学业信息/毕业去向" |

### 学生画像查询视图

| 编号 | 功能 |
|------|------|
| FR-21 | 用户应能通过**学号或姓名**进行关键词搜索 |
| FR-22 | 用户应能通过**学院、年级、性别、状态**四个下拉框进行组合筛选 |
| FR-23 | 用户应能同时使用关键词搜索和下拉筛选条件（AND 组合） |
| FR-24 | 用户应能**重置**所有筛选条件回到默认状态 |
| FR-25 | 用户应能看到筛选结果的**总数**和**分页列表**（每页固定 10 条） |
| FR-26 | 结果列表应展示：学号、姓名（带头像首字母）、性别、学院、专业、年级、状态（在学/不在学）、综测成绩、绩点、班级排名、标签（前 2 个 + 剩余数量） |
| FR-27 | 用户应能**点击任意一行**或点击"查看画像"按钮，直接跳转到该学生的个体画像视图 |
| FR-28 | 如果筛选条件导致结果为 0，应显示"未找到符合条件的学生"提示，而不是空白或报错 |

## 4. 数据需求

### 4.1 学生基础信息

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| studentId | string | ✅ | 学号，如 "01116118"，查询主索引 |
| name | string | ✅ | 姓名，如 "杨灿君" |
| gender | enum | ✅ | "男" / "女" |
| nation | string | ✅ | 民族，如 "汉族"、"维吾尔族" |
| college | string | ✅ | 学院，如 "机械学院" |
| major | string | ✅ | 专业，如 "计算机科学与技术" |
| grade | string | ✅ | 年级，如 "2021级" |
| className | string | ✅ | 班级，如 "俄语教研室15班" |
| political | enum | ✅ | "中共党员" / "共青团员" / "群众" / "其他" |
| status | enum | ✅ | "在学" / "不在学" |

### 4.2 学业与综测

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| gpa | number | ✅ | 绩点，如 9.8 |
| score | number | ✅ | 综测成绩 0~100 |
| classRank | number | ✅ | 班级排名 |
| classTotal | number | ✅ | 班级总人数 |
| majorRank | number | ✅ | 专业排名 |
| majorTotal | number | ✅ | 专业总人数 |
| scoreDelta | number | ❌ | 综测成绩较去年变化（+/-） |
| rankDelta | number | ❌ | 排名较去年变化 |
| credits | number | ✅ | 已获学分 |
| failCount | number | ✅ | 挂科门数 |
| scoreTrend | array | ✅ | 近 N 学期必修/选修成绩，格式 `[{term, required, elective}]` |
| radarScores | object | ✅ | 综测六维：`{ 思想品德, 学习能力, 实践能力, 创新能力, 身体素质, 文化素养 }` |

### 4.3 日常生活

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| cardBalance | number | ✅ | 一卡通余额（元） |
| books | number | ✅ | 本月借阅图书（本） |
| onlineHours | number | ✅ | 本月上网时长（小时） |
| leaveCount | number | ✅ | 本月请假次数 |
| dorm | string | ❌ | 宿舍地址，如 "江宁校区5栋602" |

### 4.4 校园活动

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| activityCount | number | ✅ | 总活动次数 |
| competition | number | ✅ | 竞赛次数 |
| practice | number | ✅ | 社会实践次数 |
| volunteer | number | ✅ | 志愿服务时长（小时） |

### 4.5 奖励处分

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| awards | number | ✅ | 获奖总数 |
| scholarship | number | ✅ | 奖学金金额（元） |
| honors | number | ✅ | 荣誉称号数 |
| punish | number | ✅ | 违纪处分次数 |
| tags | array | ✅ | 学生标签字符串数组，如 ["优秀学生", "CET-6"] |

### 4.6 群组统计（学院级别）

| 字段 | 类型 | 说明 |
|------|------|------|
| totalCount | number | 学院学生总数 |
| activeCount | number | 在籍人数 |
| inactiveCount | number | 不在籍人数 |
| maleCount | number | 男生数 |
| femaleCount | number | 女生数 |
| politicalDistribution | object | 政治面貌分布：`{ 中共党员, 预备党员, 共青团员, 其他, 群众 }` |
| ageDistribution | object | 年龄分布：`{ 18以下, 19, 20, 21, 22+ }` |
| provinceDistribution | array | 生源地省份数组：`[{ name, value }]` |
| minorityDistribution | array | 少数民族排行数组：`[{ name, count, percent }]` |
| comprehensiveTrend | array | 近 5 年综测平均分：`[{ year, score }]` |
| leaveTrend | array | 近 7 天请假人数：`[{ date, count }]` |

## 5. 非功能需求

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| NFR-01 | **页面加载性能** | 首次打开任意视图（个体画像/群组分析/查询）从点击到完整渲染所有图表不超过 **2 秒**（本地 Vite 环境，无后端请求） |
| NFR-02 | **视图切换稳定性** | 在三个视图之间反复切换 10 次，不应出现图表残留 canvas 报错、空白页、TypeError/ReferenceError |
| NFR-03 | **图表健壮性** | ECharts 初始化前应先校验 DOM 容器存在且有尺寸；图表应支持窗口 resize 自动重绘 |
| NFR-04 | **数据驱动** | 所有图表配置应基于响应式数据（ref/computed），当数据变化时图表应自动更新而不需要手动重建 |
| NFR-05 | **大屏适配** | 页面最小宽度 1280px，三列布局不坍塌；在 1920×1080 分辨率下所有卡片和图表完整可见，无需水平或垂直滚动 |
| NFR-06 | **加载兜底** | 生源地中国地图加载失败时，应自动降级为"按省份生源人数条形图"，不能让页面卡住或报错 |
| NFR-07 | **图片加载** | 学生人物图片应在 DOM 中直接声明原生 `<img>` 元素并绑定 `onload/onerror` 事件，加载完成后隐藏"加载中..."提示 |
| NFR-08 | **零运行时错误** | 控制台不应出现 TypeError、ReferenceError、SyntaxError 等 JS 运行时错误 |
| NFR-09 | **代码可维护性** | 所有 Mock 数据集中在一处（setup 函数内），图表配置和初始化逻辑应按视图分块注释 |
| NFR-10 | **浏览器兼容** | 在 Chrome / Edge 最新版上完全可用 |

## 6. 验收标准

当以下条件同时满足时，本阶段开发完成：

1. 三个顶层视图都能正常打开、切换、回到首页
2. 9 个 ECharts 图表全部渲染（3 个个体画像 + 6 个群组分析）
3. 查询视图能搜索、筛选、分页、点击行跳转到对应学生的个体画像
4. 跳转后，个体画像的姓名/学号/综测/雷达图/圆环图/折线图全部联动刷新，反映新学生的数据
5. 无痕浏览器窗口打开，控制台零 JS 运行时错误
6. 页面宽度缩小到 1280px 时布局不坍塌
7. README.md 可以让新接手的人 1 分钟看懂项目、1 分钟跑起来

8. Git 仓库包含 main 和 dev 分支，至少 5 次有意义的 commit，至少 1 次 merge
